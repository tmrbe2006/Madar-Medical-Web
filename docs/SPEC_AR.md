# مواصفات مدار الطبي وخطة الاستكمال

## التقنية المعتمدة — تحديث 0.3.0

واجهة TypeScript + HTML + CSS + Vite + PWA. خادم API مكتوب TypeScript ويعمل على Node.js، دون Python في الحزمة أو التشغيل. لوحة دخول حسب الأدوار وحسابات فردية يضيفها المدير.

## المنفذ في 0.3.0

أضيفت بيانات تأمين المريض ومصدر التعارف والعمر المحسوب، وإدارة ملف المريض وتعديله وحذفه المنطقي وطباعته واستعادته. أضيفت التخصصات والعيادات وتسكين الأطباء والحجوزات ونوع الزيارة، وقوائم التشخيصات والأدوية والتحاليل والأشعة.

فُصل حجز الاستقبال عن كشف الطبيب، ويشترط الكشف حجزًا مسندًا للطبيب نفسه. تُحجب ملاحظات الكشف عن المدير والاستقبال من API، وتنتقل هوية جهة السداد من ملف المريض إلى الحجز والزيارة ثم الفاتورة. أضيفت إدارة شركات وخطط وأسعار التأمين. بيانات الكشف والطلبات تحفظ نسخًا من أسمائها عند الاعتماد.

طلبات التحاليل والأشعة ووصفة الدواء لا تعني تنفيذ الخدمة أو اعتماد النتائج أو صرف المخزون تلقائيًا. هذه حلقات تشغيلية تالية يجب ربطها بالحسابات حسب المستند الفعلي. القوائم المحاسبية المتقدمة والموارد البشرية والإقامة والمزامنة والتراخيص تبقى ضمن الخطة.

## القرارات المعتمدة من د. تامر

- برنامج جديد مستقل لمركزه وللبيع إلى منشآت أخرى.
- أربعة فروع مبدئيًا، حوالي عشرة أجهزة متزامنة لكل فرع.
- عميل/منشأة يمكن أن يمتلك شركات مستقلة وفروعًا تحتها.
- استقلال حسابات الفروع، وتقارير موحدة ومقارنات على مستوى الإدارة.
- ملف مريض موحد بين فروع نفس العميل مع فصل بيانات العملاء التجاريين بعضهم عن بعض.
- تشغيل محلي كامل للكشف والصرف والتحصيل أثناء انقطاع الإنترنت، ومزامنة عند عودته.
- خوادم Windows. اختيار MySQL أو SQL Server لكل فرع. التوافق مع MySQL 5.5 وSQL Server 2008 مطلوب ويحتاج اعتمادًا عمليًا.
- بيع الوحدات بشكل منفصل أو مجتمعة؛ اشتراك دوري حسب الفروع والوحدات.
- لغتان: العربية والإنجليزية، ودعم الطباعة في الاتجاهين.
- الطبيب يسجل الشكوى والفحص والتشخيص والوصفة وطلبات المعمل والأشعة والتعليمات، مع مطبوعات مستقلة وملخص زيارة.
- عيادات، معمل، صيدلية، أشعة، إقامة ومبيت وملاحظة بالساعات، عمليات وإجراءات.
- المعمل والصيدلية يخدمان مرضى داخليين وعملاء خارجيين.
- نسب الطبيب للكشف والإجراءات والخدمات المحددة في عقده، ومن قيمة الخدمة قبل الخصم الإضافي، مع دعم الإيجار والثابت مع النسبة.
- في التأمين لا توجد خصومات إضافية. سعر كل خدمة وتحمل المريض يختلفان حسب الشركة والعقد والخطة.
- محاسبة كاملة وموارد بشرية ورواتب وسلف وحضور وانصراف.

## الهيكل المستهدف

Tenant -> Legal entity -> Branch -> Department / cost center.

ملف المريض على مستوى العميل، بينما المستند المالي يتبع شركة وفرعًا وفترة ومركز تكلفة. لا يجوز للعميل الوصول إلى بيانات عميل آخر. تجميع شركات مستقلة يحتاج ربط دليل الحسابات وإلغاءات التجميع المناسبة؛ التقارير الإدارية المجمعة لا تحل تلقائيًا محل القوائم القانونية لكل شركة.

النسخة 0.3 تمثل مرحلة تقييم لنواة واحدة، بأربعة فروع في قاعدة واحدة. ليست تنفيذًا للعزل متعدد العملاء أو للشركات المستقلة أو للمزامنة.

## قواعد مالية يجب الحفاظ عليها

1. القيد المزدوج متوازن، وجميع المبالغ تستخدم كسورًا عشرية دقيقة أو وحدات صغرى صحيحة. لا تستخدم float للترحيل.
2. كل فاتورة وبند يحتفظان بالسعر ونسبة التحمل ونسبة الطبيب وشروط الحساب وقت تقديم الخدمة.
3. حساب الأتعاب يختلف عن توقيت دفع الأتعاب. استحقاق نسبة الخدمة لا يعني صرفها فورًا.
4. التحصيل يخفض المديونية ولا يعيد تسجيل الإيراد.
5. العربون التزام/دفعة مقدمة حتى تتم تسويته وفق الدورة المعتمدة.
6. الخصم النقدي الإضافي يتحمله المركز، ولا يخفض أساس نسبة الطبيب حسب قرار المستخدم. التأمين يمنع الخصم الإضافي.
7. المرتجعات والتسويات تعكس أثر الإيراد والتكلفة والمخزون والتأمين ومستحق الطبيب بحسب الحالة؛ المدفوعات تحتاج دورة رد موثقة.
8. لا حذف للقيود المرحلة؛ عكس أو تصحيح معتمد وسجل واضح.
9. لا تغيير لأسعار ونسب المستندات القديمة عند تغيير القوائم أو العقود.
10. لا تضاعف العملية عند إعادة الإرسال. تعدد الأحداث الاقتصادية الحقيقية يظل مسموحًا بمعرفات مختلفة.

## الوحدات المتبقية ومعايير القبول

### المحاسبة الكاملة

فواتير مشتريات ومبيعات أصناف وخدمات، نقدي وآجل، مردودات كلية وجزئية، سندات قبض وصرف، تخصيص السداد على عدة مستندات، مصروفات شراء، أرصدة افتتاحية، أصول وإهلاك واستبعاد، خزائن وبنوك وتحويلات وتسويات بنكية، قيود استحقاق وتسوية، سنوات مالية وإقفال شهري وسنوي ومراجعة واعتماد.

التقارير: يومية وأستاذ ومساعد، ميزان أرصدة ومجاميع وافتتاحي وحركة وختامي، مركز مالي، قائمة دخل، تدفقات نقدية، تغيرات حقوق الملكية على مستوى الكيان، أعمار ديون، كشوف ومطابقات عملاء وموردين وتأمين وأطباء، موازنات وانحرافات، مراكز تكلفة وربحية، تقارير تفصيلية ومجمعة، وطباعة Excel/PDF.

القبول: مطابقة الحسابات المساعدة مع الرقابية؛ تسوية الأرصدة الافتتاحية؛ مردود محصل مع رد نقدي؛ فصل صلاحيات الإنشاء والاعتماد؛ تقارير تتوازن مع دفتر الأستاذ. مراجعة الضرائب والفوترة الإلكترونية والمتطلبات المحلية مع محاسب المركز والوثائق الرسمية عند التنفيذ، دون افتراض معاملة ضريبية واحدة لكل الخدمات.

### المخزون والصيدلية والمشتريات

أصناف ووحدات وتحويلات وحدات وباركود وتشغيلات وصلاحية، موردون، طلبات وأوامر شراء واستلام وفاتورة، صرف داخلي وبيع خارجي، تحويلات بين الفروع، جرد وفروقات، حد إعادة طلب، مرتجعات بالتشغيلة، تكلفة مخزون معتمدة.

القبول: منع صرف كمية غير متاحة محليًا حسب السياسة؛ عدم صرف تشغيلات منتهية؛ تطابق تقييم المخزون مع الحسابات؛ تثبيت تكلفة الصرف وعدم إعادة حساب المستند القديم عند تغير الأسعار.

### التأمين والتعاقدات

شركات حكومية وخاصة، عقود وخطط وبطاقات وأهلية وتواريخ سريان، أسعار لكل خدمة وصنف دوائي، تحمل نسبة أو مبلغ، تغطيات واستثناءات وحدود كميات ومرات ومبالغ، موافقات وتوثيقها، تجهيز مطالبات وتجميعها وإرسال/تصدير، قبول ورفض جزئي وتسويات وإعادة تقديم وتحصيل مرتبط بالبنود.

القبول: أمثلة حقيقية من العقود الفعلية؛ عدم تحميل فرق السعر النقدي على المريض تلقائيًا؛ عدم تحويل رفض الشركة للمريض دون أساس تعاقدي واعتماد؛ مطابقة المطالبات والمديونيات. التكامل الإلكتروني لكل جهة يعتمد على واجهاتها وتصاريحها، وليس متاحًا افتراضيًا.

عند انقطاع الإنترنت لا يمكن ضمان معرفة الرصيد التأميني المشترك الفوري بين الفروع. تُضبط سياسة لكل خدمة: موافقة سابقة موثقة، أو تعليق الخدمة التي تتطلب تحققًا، أو تجاوز معتمد وواضح ومسجل.

### المعمل والأشعة

طلبات داخلية وخارجية، عينات وباركود وتتبع سحب واستلام ورفض وإعادة عينة، إدخال يدوي، وحدات ومدى مرجعي حسب العمر/الجنس، نتائج أولية ومراجعة واعتماد وتعديل موثق بعد الاعتماد، معامل خارجية وتكلفة الخدمة، تقارير الأشعة والصور.

ربط أجهزة المعمل حسب بروتوكول وموديل الجهاز. ربط الأشعة يتناول DICOM/PACS حيث يتاح، ويختلف عن استيراد صورة أو PDF. الإدخال اليدوي يبقى متاحًا بتوثيق مصدر النتيجة والمستخدم والمعتمد.

القبول: عينات اختبار أو محاكاة موثقة ثم تجربة على الأجهزة الفعلية؛ منع إسناد نتيجة لمريض غير صحيح؛ تمييز الأولي والمعتمد؛ عدم توليد تشخيص أو نتيجة آلية غير موثقة.

### الإقامة والعمليات والتمريض

غرف وأسرة وحجز ودخول ونقل وخروج، حساب بالساعة/الليلة/اليوم وقواعد بداية يوم إضافي، تمريض وأوامر دواء وإثبات إعطاء، مستهلكات، عربون وحد ائتمان ومراجعة خروج، عمليات وفريق وتخدير وأتعاب وباقات وما يشمله السعر وتكلفة تفصيلية.

القبول: رحلة كشف -> ملاحظة -> إقامة -> عملية -> خروج، دون فقد خدمات أو تكرار تحميل، مع مرتجع دواء وفروق غرفة وتسوية عربون.

### تعاقدات الأطباء والموارد البشرية

عقود بتاريخ سريان حسب الطبيب والفرع والخدمة والجهة، راتب ثابت ونسبة وإيجار، توزيع أتعاب متعددة، استحقاقات وسلف ومدفوعات، كشوف حساب واعتماد التسويات. موظفون وورديات وحضور وانصراف وإجازات ورواتب واستقطاعات وسلف وربط قيود.

القبول: حالات قبل/بعد تعديل العقد، تصحيح خدمة قديمة، مردود بعد صرف أتعاب، قسط سلفة، غياب وورديات ليلية. ربط أجهزة الحضور حسب موديلها دون افتراض توافق عام.

### الفروع والمزامنة

لكل فرع خادم تطبيق وقاعدة محلية، وله سلطة تسجيل حركات مخزونه وخزينته. المزامنة على مستوى أحداث التطبيق عبر API موثق ومؤمن، وليس نسخ جداول مباشرًا بين MySQL وSQL Server.

Outbox داخل نفس معاملة العملية، وInbox بمعرف حدث فريد في المركز، وتأكيد استلام وإعادة محاولة، وترتيب وتبعيات، وإصدارات وتعامل صريح مع التعارض. معرفات المستندات والمرضى لا تتصادم. ترقيم ظاهر يتضمن الفرع وسلسلة المستند.

لا تدمج حقول السجل الطبي المتعارضة بطريقة «آخر كتابة تفوز». تستخدم إضافات/إصدارات أو مراجعة مخولة. دمج المرضى المكررين يحتفظ بالمعرفات البديلة والأثر.

القبول: فصل الإنترنت عن فرعين أثناء العمل، تشغيل الكشف والصرف والتحصيل محليًا، ثم إعادة الاتصال وإعادة إرسال نفس الأحداث وقطع الاتصال أثناء الإرسال، والتحقق من عدم ضياع أو تكرار أي حركة. الإدارة ترى آخر وقت مزامنة لكل فرع ومدى اكتمال التقرير.

### الاشتراكات والتجهيز التجاري

اختيار الوحدات والفروع حسب العميل، والتحقق على الخادم وعلى الواجهة، وتبعيات الوحدات المنفردة؛ المعمل والصيدلية يحتاجان نواة فوترة ومخزون وحسابات مناسبة. تراخيص موقعة، وتجديد وسياسة واضحة للعمل دون اتصال وفترة سماح، والوصول إلى البيانات واستخراجها عند انتهاء الاشتراك.

القبول: عدم فتح وحدة غير مرخصة بالرابط أو API، وتقييم انتهاء الاشتراك أثناء انقطاع الإنترنت، واختبار استرجاع نسخة احتياطية وتحديث إصدار بدون فقد بيانات.

## جاهزية الإنتاج

- إدارة مستخدمين فرديين وتغيير كلمات المرور وسياسات الجلسات والصلاحيات على مستوى الكيان والفرع والعملية.
- سجل تدقيق أشمل للتعديلات والاعتمادات والوصول الحساس، وحماية من التعديل خارج التطبيق قدر الإمكان.
- HTTPS وشهادات وشبكة محلية، وصلاحيات قاعدة بيانات وخادم، وتشغيل كخدمة Windows بخادم إنتاجي.
- نسخ احتياطي مشفر واختبار استعادة وخطة تعطل الخادم والكهرباء.
- قيود وفهارس وترحيلات مخطط وإصدارات، واختبارات فعلية لكل محرك قديم وكل تعريف اتصال.
- اختبارات حمل بأربع فروع وعشرة أجهزة لكل فرع، وصرف متزامن وتحصيل متزامن.
- اختبار بصري للغتين والطباعة A4، والتحقق من الروشتة والطلبات بواسطة الطبيب.
- لا يُعد أي بند هنا مكتملًا بمجرد وجوده في وثيقة المتطلبات.


## إضافة الإصدار 0.4.0

نُفذت إدارة الخدمات والأسعار، وملفات الأطباء، وأكواد تلقائية محفوظة في سجل حجز أكواد وتسلسل مستقل لكل قائمة، وتخصيص عدة فروع للموظف وصلاحيات لكل شاشة وعملية. ربط الطبيب بالحساب يحفظ معرفات الزيارات التاريخية. تغيير الدور لا يمنح حق الاطلاع على كشف طبيب آخر. أكواد السجلات المحذوفة لا تحذف من سجل الحجز. حذف المستخدم يعطله ويحفظ آثاره المالية والطبية، واستعادته ممكنة. كلمة المرور الجديدة ٤ أحرف أو أرقام على الأقل ومخزنة كتجزئة مملحة؛ لا تعرض أو ترسل كلمة المرور القديمة.

تُحفظ صلاحيات المستخدم وفروعه في access_profiles، والملف الطبي الإداري للطبيب في doctor_profiles، وبيانات حالة الخدمة وكودها في service_details. الترقية تضيف جداول دون إعادة إنشاء قاعدة البيانات. الحسابات القديمة تحتفظ بأدوارها وفروعها وصلاحيات افتراضية مكافئة. خدمات وأطباء النظام القديم يستكمل لهم كود تلقائي. النسخ الاحتياطي التلقائي قبل الترقية متاح لقواعد SQLite المحلية؛ خوادم MySQL وSQL Server تتطلب نسخها الأصلية.

الوحدات التشغيلية غير المكتملة والمزامنة والتراخيص لا تتحول إلى وحدات مكتملة بمجرد ظهور أدوارها أو صلاحياتها.


## الإصدار 0.5.0 — تسعير تسكين الطبيب

appointment_tariffs يربط التسكين ونوع الزيارة بالخدمة والسعر ونسبة الطبيب. يدعم الكشف والاستشارة والمتابعة وخدمة أخرى. تحفظ لقطة السعر النقدي ونسبة الطبيب وسعر التعاقد وتحمل المريض ضمن تفاصيل الحجز، ثم visit_links، ثم الفاتورة. التعديل الإداري للحجز يعيد التسعير، أما تعديل قوائم الأسعار فلا يغير الحجوزات السابقة أو الفواتير المرحلة. الطبيب له حساب واحد يمكنه العمل بعدة عيادات وفروع؛ تختلف الأسعار بتسكين العيادة. تفصل قوائم خدمات وأسعار العيادات والمعمل والأشعة مع بقاء صلاحية الخدمات مشتركة.

الفاتورة تختار الخدمة المحجوزة تلقائيًا. إذا كان الحجز له تسعير مخصص، يجب أن تتضمن الفاتورة خدمته بكمية واحدة. يمنع ترحيل فاتورة ثانية لنفس الزيارة قبل رد الأولى غير المحصلة. الخصم النقدي لا يغير نسبة الطبيب المحسوبة قبل الخصم؛ التأمين لا يسمح بخصم إضافي. دفتر الأستاذ وترحيل الفاتورة والتحصيل والمردود ما زالت هي النواة الحالية، وليست دليل اكتمال المشتريات أو المخزون أو القوائم المالية المتقدمة.


## الإصدار 0.6.0

تحسين عرض اكتمال الكشف، سجل سابق للطبيب من بياناته المسموحة في الفرع، ومطبوعات بشعار raster محفوظ ضمن إعدادات المنشأة. theme وskin محفوظان ضمن settings ولا يغيران صلاحيات الوصول. الحساب الجديد يعتمد تسلسلًا محفوظًا لكل أب في code_sequences وحجزًا في code_registry لمنع إعادة استعمال الكود بعد الحذف؛ لا يغير معرف حساب قديم. الحذف الفعلي محصور في الحساب غير النظامي وغير المستخدم الذي ليس له أبناء، ويُسجل في سجل العمليات.

وضع MADAR_DEMO=true يحتاج DB_PATH=data/demo.db ويرفض مسارًا آخر. التشغيل بملف 4-DEMO.cmd ينشئ قاعدة منفصلة وحسابات demo_* وبيانات تدريبية وهمية. جلسة الديمو منفصلة عن الجلسة الأساسية. البذر محاط بمعاملة ولا يتكرر إذا وجد marker demo-data-v1، ويرفض قاعدة تحتوي حسابات أو مرضى غير مهيئين للتجربة. الرسوم تستخدم snapshot الخاضعة للصلاحيات، ولا تجمع بيانات فروع غير مسموحة.


## الإصدار 0.7.0

أضيفت جداول doses وroutes وfrequencies وdurations بنفس دورة إدارة القوائم. تحفظ تعليمات الروشتة كقيم نصية تاريخية بعد الاختيار أو الإدخال الخاص، ولا تتغير بوصف القائمة أو حذفها. service_requests يحتفظ بطلب مستقل لكل زيارة وقسم وفحص، مع قيد تفرد مركب. إنشاء الطلبات وحفظ الكشف في المعاملة نفسها، والإدراج التاريخي للطلبات المنظمة محكوم بعلامة service-work-v1. الصلاحيات الجديدة lab-work وradiology-work تضاف افتراضيًا لدور القسم، وتظل الصلاحيات القديمة المخصصة محفوظة. الحالة لا تتجاوز قيد التنفيذ في هذه المرحلة؛ لا توجد نتائج معتمدة بعد.

ديمو v2 يوسع القوائم والأسماء المُركبة والتسكين والخدمات وخطط التأمين المزعومة الأسعار داخل قاعدة الديمو فقط، مع علامة منع تكرار. لا يجلب بيانات شخصية حقيقية. سلوك عرض التقارير يظهر تأكيدًا والفترة، وتوحد حدود اليوم بتوقيت القاهرة.


## الإصدار 0.8.0 — النتائج

service_results يحتفظ بمحتوى النتيجة وحالتها ورقم إصدارها واسم ومعرف المُدخل والمراجع وسبب الإعادة وتاريخ الاعتماد. الحالات مسودة ثم مرسلة ثم معتمدة؛ الإعادة من المرسل إلى المسودة تشترط سببًا. الاعتماد يحتاج صلاحية تعديل القسم وصلاحية result-approval، ويمنع اعتماد نفس المُدخل. الطلب لا يتحول completed إلا عند اعتماد النتيجة من هذا المسار. نتيجة معتمدة غير قابلة للتعديل؛ الملحق التصحيحي مرحلة لاحقة.

المعمل والأشعة يريان نتائج قسمهما وفروعهما. الطبيب يرى النتائج المعتمدة المرتبطة بكشوفه فقط في الفرع الحالي. بيانات النتيجة لا تُتاح للاستقبال، والمراجع يرى الطلب بحسب صلاحيات القسم. تخزن أسماء الأطراف وبيانات الفحص للمطبوع. رقم الإصدار يمنع الحفظ على نسخة قديمة ضمن تشغيل خادم الفرع الحالي. توجد نسخ احتياطية SQLite قبل ترقية قاعدة 0.7.0.

البحث في عيادة الطبيب يعمل على بيانات snapshot المسموحة للطبيب، ولا يرسل طلب بحث عام عن مرضى أو أطباء آخرين. سجل العمليات يستخدم فترة created_at الفعلية بدل استخدام فلاتر القيود وحدها.


## الإصدار 0.9.0

exam_definitions يخزن قوالب الفحوص وصفوف القياسات والوحدات والمرجع وسياقه ومصدره. request_details يربط الطلب بمصدره (طبيب/خارجي) وتعريفه ورقم الحجز وموعده. النتائج تحفظ قيم الصفوف والوحدات والمديات عند الإدخال، فلا تعيد كتابة الماضي عند تغيير القالب.

result_attachments يحتفظ بالصور منفصلة عن snapshot وبنوعها وحجمها وبصمة SHA-256 واسمها والمستخدم والتاريخ وحالة الإتاحة. تنزيل الصورة يحتاج جلسة وصلاحية القسم والفرع، أو طبيب الزيارة بعد الاعتماد. لا يعيد snapshot بيانات الصور الثنائية. تُمنع تغييرات الصور أثناء المراجعة وبعد الاعتماد. الصور PNG/JPEG/WebP حتى 8 × 2MB لكل طلب؛ ليست DICOM/PACS. تبقى البيانات ضمن قاعدة الفرع ونسخها الاحتياطية.

الحجز الخارجي ينشئ طلبات دون زيارة وهمية أو قيد مالي. يعطي الاستقبال اختيار مرضى محدودًا وفق صلاحية الحجز، دون إعطائه نتائج أو صورًا سريرية. مسار الفواتير الخارجية مرحلة منفصلة.


## 0.10.0 — تعريف التحليل وبارامتراته
تعريف كل تحليل يحتوي قائمة بارامترات بمعرفات ثابتة وترتيب محفوظ ووحدة ومرجع مستقلين، مخزنة داخل سجل exam_definitions. عند الحجز تُنسخ القائمة في request_details؛ كل صف من النتائج يحمل parameter_id للربط ببارامتر الطلب، مع snapshot للعرض التاريخي. الحذف من التعريف لا يحذف نتائج المرضى السابقة. الطلبات الجديدة تتحقق من تطابق المجموعة كاملة على الخادم؛ الصيغة القديمة مدعومة للطلبات التاريخية. لا توجد جداول SQL منفصلة لكل اسم تحليل.
